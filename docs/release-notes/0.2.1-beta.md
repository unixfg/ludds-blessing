# Ludd’s Blessing 0.2.1 community beta

Version 0.2.1 is the first public community beta. It is a release-readiness and
portability hardening pass that keeps the strict uncompressed Starsector
`0.98a-RC8` / save-format `0.6` write gate.

## Highlights

- Save discovery and remembered roots are more resilient, including older
  descriptor layouts and bounded Windows Documents, OneDrive, VirtualStore,
  installation, and custom `vmparams` locations.
- Existing player inventory, colony Storage, and colony Local Resources can be
  edited. Recognized catalog items and blueprints can be added to supported
  colony containers without requiring a Starsector mod. The validated local
  catalog stays open after each addition so multiple stack changes can be
  staged before the user closes it; see
  [#5](https://github.com/unixfg/ludds-blessing/issues/5).
- Officers have bulk Unlearned, Learned, and Elite controls, with a pinned
  roster while abilities scroll.
- Game Settings Profiles can manage player maximum level, skill and story
  points per level, officer maximum level, and the officer elite-skill cap for
  verified installations. Applies are bound to the exact settings revision,
  create an external backup, and require Starsector to be closed and restarted;
  the feature does not use or install a mod. Save XP and target-level simulation
  fail closed per affected player/officer track when the rules used by the RC8
  simulator differ or cannot be verified; direct skill and unspent-point edits
  remain available.
- Sessions and reviews are bounded, superseded records are released, and
  remembered save roots can be reviewed or forgotten. Manual-root settings use
  durable replacement rather than in-place truncation.
- Native filesystem permissions, installation validation, and discovery have
  been tightened in preparation for macOS and Linux validation.

## Distribution and security

- The Windows release is one standalone executable with no installer or
  updater. It uses an already installed Microsoft WebView2 Evergreen Runtime
  and does not download one; Microsoft may service that runtime independently.
- Rust is pinned to a specific toolchain, external GitHub Actions are pinned to
  reviewed commit SHAs, and scheduled RustSec and production npm audits are
  part of the repository checks.
- Release candidates are retained for review and smoke testing. Publication
  takes the verified executable from that exact candidate instead of rebuilding
  it.
- The public download list contains only the standalone executable. GitHub
  provides the corresponding tagged source archives and immutable-release
  attestation on the same page. The retained review candidate also contains
  notices, an SPDX source/build SBOM, descriptive provenance, and SHA-256
  manifests for release verification; those are not separate public downloads.

This remains an unsigned beta. Windows SmartScreen may warn before launch.
Verify the executable against the SHA-256 digest shown by GitHub, retain
Starsector’s own backups, and use Save Copy for the first test of any important
campaign.
